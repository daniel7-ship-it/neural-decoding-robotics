# Replay reliability milestone — 2026-10-28

The replay contract was saved in `docs/replay-timing-contract.md` before implementation. The dashboard and headless tests use the same `ReplayEngine`. Window times are acquisition-end availability timestamps from `supervised.generate_session`. The engine seeks to the first available window at/after the selected start, resets gate history, and waits until absolute recording time reaches each availability timestamp. At every20ms physics tick, the previous unexpired command is applied first; decisions issued at the tick can affect the next interval. Irregular gaps contain no synthetic windows and the existing250ms command TTL expires naturally. Nonfinite, duplicate, decreasing and mismatched timestamps are rejected.

The engine consumes windows in order exactly once. It holds the final recording open through the next100ms decision interval, then produces a zero-command terminal frame and becomes idempotently complete. Empty and beyond-end recordings complete immediately; one-window and final-window seeks were tested. The viewer no longer automatically loops: it saves a trace and complete metrics, leaves the final summary visible, and waits for Restart or a model/condition selection. Closing mid-run saves a partial trace; the unfinished block is excluded from completed-episode metrics. No old artifact is overwritten because each run uses a UUID filename.

Saved JSON traces in `artifacts/neural-replay-runs/` include checkpoint and source-recording hashes, noise seed, condition/session/start time, decoder probabilities, issue and eligibility times, every applied physics command, final/partial reason, metrics, and final robot state. Labels stay in the scorer. The dashboard displays the issued yaw separately from the applied yaw. Rest transition carryover and new activation/change after rest entry remain separate; the latter has no washout and should not be called established rest. The final summary is scoreable from the applied-command trace: `artifacts/verify-completed-trace.py` independently reproduced its counts and checked the terminal zero frame.
